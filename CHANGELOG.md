# Changelog

All notable changes to Ream.st's status page (status.ream.st) are documented here.

Since v26.10.23 this project uses [Date Versioning](https://datevers.ing) (`YY.MM.DD`, the UTC release date, with `-1`, `-2`… for later releases the same day); earlier releases used Semantic Versioning.

## v26.11.13

### Changed

- The status page's Imprint (status.ream.st/legal/imprint, from `legal.company` in `.githup.yml`) gives Stux Group Ltd's new registered office: 124 City Road, London, EC1V 2NX, England (was 82a James Carter Road, Mildenhall, England, IP28 7DE). The company number and "registered in England and Wales" are unchanged

## v26.11.08

### Changed

- The page's description and the README say the sites are "checked regularly" instead of "every 5 minutes". GitHub runs the 5-minute schedule best-effort, often much less often, and GitHup now shows the real measured check rhythm on the page. The schedule itself is unchanged
- The CHANGELOG intro no longer also says the project follows Semantic Versioning

## v26.11.06

### Added

- `scripts/badge-icons.py` (copied from StuxGroup/Services, set to Ream.st's colours) and `scripts/favicon-set.py`, which build the page's badge icon and its favicon set in `icons/`

### Changed

- The page's logo and favicon are its own **Ream.st Status** badge icon (the Ream.st mark on a round avatar with a heartbeat badge) instead of the plain Ream.st logo and icon, with GitHup's favicon set (`favicon.ico`, the Apple touch icon and the manifest icons) built from it rather than GitHup's defaults. The README's header shows the same icon and is titled Ream.st Status
- New branch flow: work and releases go onto `test` and reach `main` only through a pull request. `commit.sh`/`commit.bat` refuse to release on `main` and print the push and pull-request commands, and CONTRIBUTING describes the flow and how to rebuild the icons
- The page is also rebuilt when `icons/` changes on `main`

## v26.10.23

### Added

- `tests/version.sh`, which checks that `VERSION.md` is a valid Date Version, a real calendar date not in the future, and the same as the newest entry in this changelog

### Changed

- Switched from Semantic Versioning to [Date Versioning](https://datevers.ing): releases are numbered by their UTC release date as `YY.MM.DD`, with `-1`, `-2`… for later releases the same day. This release follows v1.0.1
- `commit.sh` and `commit.bat` refuse a `VERSION.md` that isn't a valid Date Version or is dated in the future (UTC), and warn when it's dated before today
- `README.md` and `CONTRIBUTING.md` describe Date Versioning and the release steps

## v1.0.1

### Changed

- `max_response_time` raised from 3 to 15 seconds, so a slow but working Ream.st is no longer shown as degraded

## v1.0.0

### Added

- The Ream.st status page, built with GitHup and deployed to GitHub Pages at status.ream.st
- Monitors for Ream.st, Multi.st, Multi.st Twitch and Multi.st YouTube (moved from status.stux.group) and the Ream.st media CDN
- Boring Legal Stuff hub with its six sub-pages, a 404 page, a sitemap and `robots.txt`, generated by GitHup
- A 5-minute check with `fill-gaps` (up to 4 checks, 5 minutes apart, when GitHub runs the schedule late), incident Issues, and an hourly rebuild
- `dev-server` (with `DEV_MODE` on by default and `--no-dev-mode`) and `commit` scripts
